# Testing and QA Workflow

This workflow ensures that code generated by AI or written by developers is verified through automated tests, maintaining reliability and preventing regressions.

1. **Architect Test Plan**:
   - Before writing tests, review `architecture.md` and `project-overview.md` to understand the feature's requirements and constraints.
   - Identify the critical paths, edge cases, and failure modes that need testing.

2. **Develop Tests** (`/test`):
   - Write automated tests (Unit, Integration, or E2E) for the implemented features.
   - Follow the project's standard testing framework (e.g., Jest, Vitest, Playwright).
   - Ensure tests are deterministic and do not rely on flaky external states.

3. **Execute & Verify**:
   - Run the test suite to ensure all new and existing tests pass.
   - If tests fail, diagnose the root cause: is it a bug in the code, or a flaw in the test itself? Fix accordingly.

4. **Review**:
   - Verify that test coverage is adequate for the new feature.
   - Ensure test descriptions are clear and explain *what* behavior is being verified, not just *how* it's implemented.
